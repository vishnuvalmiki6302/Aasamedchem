# AASAMED — Lab Inventory & Order Management System

A full-stack web application for managing laboratory chemical inventory and seller orders, with role-based access, smart unit conversion, and real-time order lifecycle management.

## 1. Project Overview & Tech Stack
AASAMED serves two main users:
- **Admins:** Manage inventory, review and approve/reject orders.
- **Sellers:** Browse products, use the cart system with auto-unit conversion, and place orders.

**Tech Stack:**
- **Frontend:** React 19 (Vite), React Router, Axios, Custom CSS.
- **Backend:** Node.js, Express.js.
- **Database:** MongoDB Atlas (Mongoose ODM).
- **Authentication:** Stateless JWT (JSON Web Tokens).

## 2. System Architecture & Data Flow
- **Authentication:** Users log in, receiving a JWT stored in localStorage.
- **API Communication:** An Axios interceptor automatically attaches the `Bearer` token to all backend requests.
- **Authorization:** The backend uses middleware (`protect` and `requireAdmin`) to verify the token and enforce role-based access before processing any API request.

## 3. Database Schema & Data Modelling
Prices and stock quantities are strictly stored in **base units** (`g` for weight, `ml` for volume, `item` for count). This ensures calculations are always uniform (`qty × pricePerBaseUnit`).

### Key Models
**Product:**
```js
{
  name: String,
  sku: String, // Unique identifier
  category: String,
  baseUnit: 'g' | 'ml' | 'item',
  pricePerBaseUnit: Number, // Floating point. e.g., ₹0.05/g
  stockQuantity: Number     // Always stored in base units
}
```

**Order:**
```js
{
  user: ObjectId, // The seller who placed the order
  items: [{
    product: ObjectId,
    orderedQuantity: Number,   // What the user typed (e.g., 2)
    orderedUnit: String,       // What the user selected (e.g., 'kg')
    convertedQuantity: Number, // Backend-calculated (e.g., 2000g)
    lineTotal: Number          // convertedQuantity × pricePerBaseUnit
  }],
  totalAmount: Number,
  status: 'Pending' | 'Approved' | 'Rejected'
}
```
*Note: `convertedQuantity` and `lineTotal` are saved permanently so historical orders don't break if product prices change later.*

## 4. Unit Conversion & Precision
Sellers can order in human-friendly units (like `kg` or `L`). The system handles conversions seamlessly:

1. **Conversion Logic:** 1 kg becomes 1000g. Handled by a shared utility function.
2. **Frontend Preview:** The frontend runs the conversion to show live price updates in the cart.
3. **Backend Authority:** When submitted, the backend **recomputes** the conversion and price to prevent tampering.
4. **Precision:** All database storage and backend math use standard floating-point numbers. Rounding (`.toFixed(2)`) is strictly applied on the frontend right before displaying Rupee values.

## 5. Running the Project Locally

**Prerequisites:** Node.js 18+ and a MongoDB connection.

### Backend Setup
```bash
cd backend
npm install
# Create a .env file:
# PORT=5000
# MONGO_URI=mongodb+srv://<your-cluster-url>
# JWT_SECRET=your_secret_key

npm run seed   # Generates test users & products
npm run dev    # Starts API on http://localhost:5000
```

### Frontend Setup
```bash
cd frontend
npm install
npm run dev    # Starts React on http://localhost:5173
```
